# 发票报销物品验收单

## 快速使用

| 项目 | 说明 |
|---|---|
| 输入 | `templates/` 内 Excel 模板，`data/` 内 PDF/图片票据。 |
| 配置 | 模板及命令行参数；低置信 OCR 品名自动补全后仍建议对照原票确认。 |
| 运行 | 双击本目录唯一的 `run.bat`，参数原样传递。 |
| 输出 | 模块根目录带时间戳的验收单 XLSX 和 `out/` 内追溯 JSON。 |
| 环境检查 | 运行根目录 `check.bat`；使用共享 `../python/python.exe`，不回退系统 Python。 |

## 批量打印发票 PDF

把待打印的票据放进 `data/`，双击 `invoice_pdf.bat`，即可按文件名顺序把图片和 PDF 合并成一个多页 PDF，每份一页，方便整批打印。

| 项目 | 说明 |
|---|---|
| 输入 | `data/` 内 JPG/JPEG/PNG/BMP/TIF/TIFF/WEBP 图片与 PDF，按文件名排序。 |
| 配置 | `--input 目录` 指定其它输入目录，`--output 文件.pdf` 指定输出路径。 |
| 运行 | 双击 `invoice_pdf.bat`；参数原样传递，如 `.\invoice_pdf.bat --no-pause`。 |
| 输出 | 模块根目录 `物品验收单_时间戳.pdf`（与验收单 XLSX 同名不同扩展名），每次新文件名，不覆盖已有文件。 |
| 环境检查 | 运行根目录 `check.bat`；使用共享 `../python/python.exe`，不回退系统 Python。 |

每页统一为 A4 横向：图片和 PDF 的每一页都缩放到完整铺满页面，不留白、不裁剪；为保证各种原始比例都铺满 A4，极少数票据可能有轻微横纵比例变化。打印时无需调整缩放。PDF 页会渲染为图片，文字不可搜索或选中，但打印效果一致。

命令行无人值守运行可在当前 PowerShell 设置 `$env:DATA_ANALYSIS_NO_PAUSE='1'`，使失败时直接返回退出码；该设置不取消 Raman 无参数单谱模式的输入提示。检查后可用 `Remove-Item Env:DATA_ANALYSIS_NO_PAUSE` 移除。原始输入及现有输出位置保持原有约定。

将一份已填好的 Excel 样本放入 `templates/`，待处理票据放入 `data/`，双击 `run.bat`。程序清除样本的旧明细，填写本次票据，生成 `ER/物品验收单_年月日_时分秒.xlsx`。每次使用新文件名，不覆盖模板、原始票据或旧结果。

- 自动读取 `templates/` 内唯一的 `.xlsx` 模板，排除 Excel 的 `~$` 临时文件；多模板时需用 `--template` 指定。
- 递归读取 PDF、JPG/JPEG、PNG、BMP、TIF/TIFF、WEBP。多页 PDF、多帧 TIFF 和一页上下排放的多张发票分别处理。
- PDF 优先读取文字及坐标；无可用文字层时渲染后执行本地中文 OCR，图片直接执行本地 OCR。正常运行不联网、不上传票据。
- 支持包含“项目名称、单位、数量、单价、金额、税率、税额”的标准电子发票，一张发票可以有多项。红字/折扣行、缺少完整明细的票据、清晰度不足或其它版式会报错，不能保证所有票据类型通用。
- 每张发票检查数量×原票单价、不含税金额、税额和价税合计。任何票据失败时，本次整体不生成 Excel；重复文件或重复发票号码也会报错，避免漏报或重复计入。
- **低清图片**：先按 Lanczos 放大到长边 3000 像素（原为双线性 2000）。数量与长小数单价被合成一个词框时，数量只取自身列的独立识别结果，单价则按多个列边界偏移重识别，并附上去掉数量前缀的整行识别串作为候选；最终由「数量×单价=金额」挑出唯一解。形近字（如首位 `1` 被读成 `[`）与全角数字只在通过票面校验时才允许还原，出现多个通过校验的候选或全部不过校验时仍拒绝，不静默改数。
- 识别失败时自动换用增强对比/锐化、灰度高倍放大两档预处理重试，仍走完整校验；控制台打印成功的档位与数值校正记录，追溯 JSON 写入 `ocr_profile` 与 `number_repairs`。文字层 PDF 不重试。
- **低清品名漏字/形近错字**：「腈」（月+青）这类字在低清票面上可能被整字漏掉，或判成「晴/睛/腊/腩」等同声旁高频字。仅对低置信、单行单框的 OCR 品名，用 3000 像素原图裁剪做 4 种独立预处理的二次识别；形近字只在能构成已知材料词形（丁腈、腈纶、腈棉）时归一，且只有多个变体一致地给出「相对原结果仅补回同一个字」才采用。任何改写、插入位置歧义或证据不足都保留原值并提示复核，绝不静默增删汉字。控制台打印补全前后文本，追溯 JSON 写入 `name_repairs`（含每个变体原始识别文本与票数）。

## 填写位置与金额口径

第5行为表头，A至E列分别为物品名称、数量、单价、总值、备注。明细从第6行开始，合计行按 A 列的“合计金额”定位。

- **B4:C4 保持合并，只写 B4**，日期取运行时 `date.today()` 的系统本地日期，以模板原有中文日期文字样式显示。
- 名称填写原票完整文字，包括 `*税收分类*` 前缀，例如 `*橡胶制品*丁腈植绒手套`，不截取后半段。长名称也完整存入单元格；模板原有列宽、字体和换行样式保持不变，固定版式下可能显示截断，可在公式栏查看完整名称。数量按原票填写。总值为各行不含税金额加该行税额；单价为含税总值除以数量，保留12位计算精度，显示按明细区统一格式（默认两位小数）。没有使用总税额比例分摊估算。
- 清除模板中的全部旧明细和旧备注，填写新的金额大写与数字合计。填报单位和验收/经办栏保持模板内容，程序不虚构签名。
- 保持模板字体、边框、列宽、已有行高、打印配置、其它工作表及合并方式。明细区 B/C/D 列（数量、单价、总值）统一按首个明细行第6行的样式，避免模板个别行被单独设成3位小数导致同一张单显示位数不一致；其余单元格样式仍逐行沿用模板。项目数不超过现有明细容量时，不移动合计与签名行；超出时复制最后一行明细的样式扩展，并平移合计和签名。复杂公式、图形等模板在需扩展时会拒绝处理。
- 仅替换工作簿内目标 worksheet XML 中的必要内容；不经过整表重建或样式转换。

## 运行速度与多文件

- OCR 引擎使用 4/4 ONNX 线程。本机交错实测：相比 2/2 线程，单张图片推理快约 1.9 倍，且逐框识别文本完全一致；`rec_batch_num` 保持默认 6，改成 1 虽更快但会改变个别识别文本，未采用。
- 明细列合并时，单价候选先走零成本来源（整行识别串去数量前缀、形近字还原），只有票面校验不过关才逐个做偏移重识别并命中即停，每张图的单元格二次识别从 7 次降到 2 次。
- 默认串行处理。本机实测多 worker 线程/进程并行会因 CPU 争抢而变慢（8 张图最优仍是单 worker），因此默认 `--workers 1`；换到核心数更多的机器可试 `--workers 2`~`4`，每个线程独占一套 OCR 引擎，输出与串行一致，追溯 JSON 记录 `parallel_workers`。
- 文字层 PDF 只读取文字与坐标，不经过 OCR，几乎不占时间；低清图片才走放大与重试。
- 品名补全只在低置信 OCR 品名上触发（4 次纯识别），本机交错实测当前样本额外开销约 0.13 秒（+2.3%）；置信度足够的品名一次都不调用。

每次运行另在 `out/` 生成对应 JSON，保存输入文件、页号、发票号码、各行原始金额和处理口径，方便核对。该记录不增加 Excel 工作表或备注内容。自动补全的品名已由多个独立识别支持，仍建议对照原票确认；未获足够证据的低置信品名由控制台提示复核。

## 人工品名核对

可在 `data/name_corrections.json` 保存已对照原图核实的品名，仅允许修正文字，不允许覆盖数量或金额。键为发票号码、从1开始的明细序号，每项包含 `recognized`（识别原文）、`name`（核实后的名称）、`reason`（依据）。识别结果与保护条件不匹配时停止，避免误用于另一种结果。识别原文和修正依据也会写入 JSON 追溯记录。

低清品名自动补全会先于本表执行，因此 `recognized` 应填写**补全后**的文本（例如本样本为 `*橡胶制品*丁腈植绒手套`）；若按补全前的 `*橡胶制品*丁植绒手套` 填写，程序会因识别结果已变化而停止并提示复核。只有自动补全未命中、或补全后仍需人工改名的情况才需要本表。

## 运行环境与命令

启动器使用项目共用的 `../python/python.exe`，禁用用户 site-packages。ER 的 OCR/PDF 依赖与模型统一放在 `../python/Lib/site-packages/`，与 Ra、Raman、CLSM 共用项目运行时。未修改 Conda 或系统环境；原有 NumPy、Pillow 等包版本保持不变。

```powershell
.\run.bat
.\run.bat --no-pause
.\run.bat --no-pause --data .\data --template .\templates\物品验收单.xlsx
.\run.bat --no-pause --workers 2
```

成功返回0并关闭窗口；失败返回1并停留显示错误，`--no-pause` 可关闭失败暂停。输出文件被打开也不会强制关闭 Excel；每次生成新的文件。

`data/`、`out/` 和 ER 目录下的生成 Excel 均不纳入 Git。迁移到其它电脑时，整个项目连同共用的 `python/` 一起复制。ER 不再保存独立的 vendor 包目录；依赖统一记录在 `python/requirements.txt`，可从项目根目录重建：

```powershell
.\python\python.exe -m pip install -r .\python\requirements.txt
```

正常启动不会自动安装或下载。

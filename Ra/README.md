# Zygo 面粗糙度 Ra 批量提取

从 Zygo NewView 界面截图中读取 **面粗糙度 Ra**（`Measure Controls` 面板，单位 nm），
按区域分组求平均输出 Excel 表格；同时把每张图的 **Oblique Plot（三维表面图）** 裁出来
存成 PNG，方便直接贴到报告 / PPT 里。

> 只提取面粗糙度。`Surface Profile` 面板里的线粗糙度（µm）不提取。

---

## 快速使用

### 方式一：一键启动（推荐）

**双击 `run_ra.bat`**，按提示输入每个区域取几张图（填 5 = 只读 `XX-1` ~ `XX-5`；直接回车 = 读取该区域全部图片）。它会自动：

1. 调用上一级目录的便携 Python（`..\python`），检查 numpy / Pillow / openpyxl 依赖
2. 在脚本所在目录扫描并处理所有截图
3. 正常结束后窗口**自动关闭**；只有出错时才停住等按键，方便看报错

也可命令行传参：

```bash
run_ra.bat 3                # 每个区域只读序号 1~3 的图
run_ra.bat --batch 3        # 等价写法
run_ra.bat --no-plot        # 不导出三维表面图
```

> 若 `ra_results.xlsx` 正被 Excel 打开，脚本会自动关闭该工作簿再重新写入，
> 不影响其它 Excel 窗口；关闭时未保存的改动会丢失。

### 方式二：直接跑 Python

```bash
python extract_ra.py
```

脚本会自动扫描**脚本同级的 `data` 文件夹**下的所有图片（`*.bmp` / `*.png` / `*.jpg` / `*.jpeg`），
按文件名里的数字自然排序。**区域按文件名前缀认定**：`3-4.bmp` 就是区域 3 的第 4 张，`Si-2.bmp`
就是区域 Si 的第 2 张——前缀不限数字，**前缀相同即同一区域，前缀不同即不同区域**，
各区域的张数不必相同（多一张少一张不会把后面的区域挤错位）。
带 `--batch N` 时每个区域只读序号最小的 N 张（`XX-1` ~ `XX-N`）；不带 `--batch`（双击 bat 直接回车）
则把该区域的所有图片都读进来。
文件名不是「前缀-序号」格式时（例如 `1.bmp`、`2.bmp`），退回用 `--batch` 每 N 张一组（默认 5）。
截图只需丢进 `data/`，不用和脚本混在一个目录里。

输出到脚本同目录：

| 文件 / 目录 | 说明 |
|---|---|
| `ra_results.xlsx` | 主表格：汇总区 + 各文件明细 |
| `out/` | 每张图裁出的三维表面图，与原图同名（`1.bmp` → `1.png`）。每次运行**结束后**会删掉本次没有产出的旧 PNG（被看图软件占用时给出警告），源图删掉或改名后不会留下过时结果。每个区域另有两张代表图加后缀：`1-3_medoid.png`（离区域均值最近）、`1-2_min.png`（区内 Ra 最小） |
| `out/min/`、`out/medoid/` | 上述两张代表图各复制一份，按类别分开存放，翻图时直接进对应文件夹 |

**整个文件夹可以直接复制到任何位置使用**，路径全部基于脚本自身位置，无需修改。

### 目录内容

| 文件 | 用途 |
|---|---|
| `run_ra.bat` | **一键启动**（双击运行） |
| `extract_ra.py` | 主处理脚本（含 bat 编码自修正，只有一个 py） |
| `README.md` | 本说明 |
| `data/` | **放待处理的 Zygo 截图**（脚本默认读这里） |
| `out/` | 自动生成：三维表面图 PNG |

> 早先独立的 `_to_gbk.py` 已并入 `extract_ra.py`，无需再单独维护。

## 三维表面图裁剪

每张截图里的 `Oblique Plot` 面板会被裁出来，单独存成 PNG：

- **裁剪框**：`(669, 75) – (1271, 400)`，尺寸 602×325
- **包含**：三维彩色表面图、右侧色标及其数值（+9.39321 / µm / -0.53905 等）、
  三轴刻度（`0.0000 mm` / `0.0706` / `0.0530`）
- **不含**：界面边框、标题栏、其它面板，背景为纯黑，贴到白底文档里边缘干净
- **格式**：PNG 无损，插入 PPT / Word 不会二次压缩失真

裁剪区域是纯黑底，用 BMP 行偏移只读该块（约 0.6 MB / 张），比整图解码快得多。

若某张图不是 1917×1003 的界面截图，会被跳过并给出提示，不会产出错位的图。

## 每区代表图（medoid / min）

所有 Ra 读完后，每个区域自动挑出两张代表图，文件名直接带后缀。「区内」指文件名前缀相同的一组
（如 `3-*.bmp`）：

| 后缀 | 含义 | 用途 |
|---|---|---|
| `_medoid` | 区内 Ra 与**区域平均**最接近的一张 | 代表该区域典型形貌 |
| `_min` | 区内 **Ra 最小**的一张 | 代表该区域最平滑的形貌 |

同一张图同时满足两个条件时，两个后缀都加（`1-1_min_medoid.png`），表格该行填色按 `min`
显示（即浅绿）。文件名后缀与表格填色一一对应：

- 浅绿 = 区内 Ra 最小（`_min`）
- 浅橙 = 区内最接近区域均值（`_medoid`）

表格底部有一行小字图例；控制台也会打印每区选中的两张图，如
`区域1: medoid = 1-1.bmp (Ra=1.948)   min = 1-2.bmp (Ra=1.368)`。

两张代表图除了留在 `out/` 根目录，还会各复制一份到 `out/min/`、`out/medoid/`，
按类别分开存放；子文件夹每次运行也会同步清理，不会攒下旧图。
同一张图同时满足两个条件时，两个文件夹里都会有它。

> 用逻辑文件名做后缀而不是改源截图名，`data/` 里的原图始终保持不变。
> 加 `--no-plot` 时不出 PNG，但表格填色照旧。

## 表格结构

与示例一致：

```
| 粗糙度（平均） | 区域1 | 区域2 |     <- 区域号
|   2.468    | 4.053 | 0.883 |     <- 各区域平均 Ra (nm)
```

下方附各文件明细（文件、区域、Ra、PV、rms、单位），便于溯源核对。
明细里 `_min` / `_medoid` 代表图所在行整行填色（浅绿 / 浅橙），表格底部带图例。

### 版式说明

两块表格同宽、共用列宽，边缘对齐，视觉上是一个整体：

- **汇总区**：标题列占 1 列，其余列平分给各区域，区域之间列宽一致。区域数多时
  自动增加列数保证等分，补出的列平摊到明细区各数据列，不会出现空白列。
- **统一规则**：全黑细线边框覆盖每个有内容的单元格；表头加粗 + 浅蓝底；
  全部列居中；数值写真数值（3 位小数格式），
  不会出现 Excel 的"数字以文本形式存储"绿色三角。
- **冻结窗格**：滚动时明细表头保持可见。

> 若区域数多于明细列数（例如 100 个文件 = 20 个区域），整表会自动加宽以容纳。

## 数据来源与识别方式

界面上的 Ra 数值位于 `Measure Controls` 面板，坐标固定（基于 1917×1003 截图）：

| 字段 | 行 y | 数值列 x | 单位列 x |
|---|---|---|---|
| PV | 330–349 | 326–462 | 488–516 |
| rms | 358–377 | 326–462 | 488–516 |
| **Ra** | **386–405** | **326–462** | **488–516** |

数值右对齐，右端固定在 x=451。

**识别流程**：ROI 二值化 → 按列投影切分字形 → 归一化到 12×16 → 与 0–9 和小数点的
点阵模板做汉明距离匹配，取最小者。

**性能**：BMP 24bit 无压缩，直接按行偏移 `seek` 只读 ROI 区域，不解码整幅图。
单文件 7 ms，10 个文件纯提取 70 ms（对比 PIL 整图解码 227 ms）。

## 可靠性验证

在 10 张样本图（Ra、PV、rms 三组字段，共 173 个字形）上做了三层验证：

1. **像素级全命中** —— 173 个字形的最佳匹配汉明距离全部为 **0**（像素完全相同），
   最小判别裕度 24（出现在最容易混淆的 0 / 8 之间），判别无歧义。
2. **双路交叉验证** —— 用完全不同的第二条实现路径（PIL 整图解码 + 原始位图精确比对
   / 等尺寸 IoU）独立复核，10/10 文件的 Ra、PV、rms **全部一致**，全部字形最小 IoU = 1.0000。
3. **肉眼核对** —— 曾用裁剪预览图逐条与界面截图比对，10 个 Ra 值全部一致
   （该预览图功能已按要求移除，仅保留结论）。

## 自检与容错

脚本会在以下情况给出明确提示，不会静默出错：

- 图像尺寸不是 1917×1003 → 跳过并说明"非本流程可处理的截图"
- 未能识别出有效 Ra → 跳过并说明可能原因
- 单位区与首张图不一致 → 告警（防止混入不同界面版本）
- 判别裕度过低 → 在该行标注 `[低置信, 建议与截图核对]`
- 扫描输入时自动排除脚本自身的输出产物（`ra_results.xlsx`）
- **Excel 正开着 `ra_results.xlsx`** → 提示"请关闭 Excel 后重跑"，退出码 4。
  注意此时不会写出任何文件（因为 xlsx 是唯一产物），但**结果仍会完整打印在屏幕上**，
  数值不会丢。

## 注意事项

### 修改 run_ra.bat 后无需手动转码

Windows 的 `cmd.exe` 按系统 ANSI 码页（本机 **936 / GBK**）解析批处理文件。
如果 `run_ra.bat` 存成 UTF-8，中文注释的字节会被 cmd 拆成乱码命令，
直接导致启动失败（报"不是内部或外部命令"）。同理，批处理必须用 **CRLF** 换行，
纯 LF 会让括号块解析错乱（报"此时不应有 ----"）。

**`extract_ra.py` 每次运行都会自动检查并修正** `run_ra.bat`：

- 存成 UTF-8 → 自动转 GBK
- 用了纯 LF → 自动转 CRLF
- 本来就是 GBK + CRLF → 不动文件（不产生多余写盘）

修正时会打印一行 `[提示] 已自动修正 run_ra.bat ...`。

> 万一 `run_ra.bat` 已被改坏、双击跑不起来：
> 在命令行执行一次 `python extract_ra.py`，bat 就会被自动修好。

### 中文乱码的原理

本机 `locale.getpreferredencoding()` 返回 `utf-8`，但 cmd 控制台代码页是 936。
两者不一致时，Python 写出的 UTF-8 字节会被 936 控制台显示成乱码。

`run_ra.bat` 的做法是：先探测 `chcp` 拿到当前代码页，再设
`PYTHONIOENCODING=cp936`（并置 `PYTHONUTF8=0`），让 Python 输出与控制台码页一致。
这样无论控制台是什么码页都能正常显示中文。
